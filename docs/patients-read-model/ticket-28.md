# Ticket 28: bounded same-cut recovery

Implements the authorized backend scope of [issue 28](https://github.com/khaoxkongz/ncd-api/issues/28) after ticket 27 integration `649f2139eaa0569bc3c79acf72a3a0640cd0d00f`. It keeps full previous output and actual source provenance through source, stage, transport and worker failures. Recovery uses the existing public Builder and Reader interfaces and existing six HTTP controllers. The deployment default remains legacy; activation remains blocked. Dashboard implementation is deferred to issue 32, and actual rendering, error/freshness display, page performance and visible 24-hour acceptance remain unmet.

## Compatible work and fixed budgets

A managed `build` can adopt the same settled failed or ready candidate for the exact signed immutable source. A private bounded journal binds manifest/signature, trusted producer key, supported history/domain, identity-finalization policy, all schema/dictionary/codec/arithmetic versions, declared budgets, original wall/monotonic elapsed lower bounds, captured calculation clock/timezone, and count/content/index inventories. It is created before source scanning, so a zero-stage transport failure can retry in its occupied slot after the exact transport is repaired. A changed cut or policy cannot reuse its output; changed run budgets are rejected.

Four durable checkpoint groups preserve actual immutable boundaries:

| Group | Complete work retained                                                                                                   | Partial or incompatible output                                                                                            |
| ----- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| A     | Verified raw staging and type inventory                                                                                  | Remove partial input/dependents; ingest the exact cut again.                                                              |
| B     | Full baseline ETL, identity finalization once, stable summary row IDs                                                    | Replace the entire summary from A; never hash partially finalized rows again.                                             |
| C     | Dictionary, daily Card/expense/membership facts, both monthly families, prepared scopes, final date metadata and indexes | Remove all candidate derived output and scratch while retaining verified A/B.                                             |
| D     | Passing comparisons, six snapshots and full actual component inventories                                                 | Reverify C, remove partial snapshots and repeat validation. Verified D can finish after staging has already been removed. |

Daily/date-month mutations and shared chunk/directory/scope writes stay together in C. Downstream stages no longer mutate finalized summaries. Actual BSON contents and required indexes are checked before a group is reused. A progress flag or matching count alone is insufficient. Corrupt output invalidates the group and its dependents; cleanup remains within the same occupied slot and is verified before replacement. Both slots, staging, journal, ledgers, indexes and scratch remain charged to the original storage cap. Prior measured resource peaks survive compatible retry.

Resume atomically advances the fence and changes owner/run under the control document. A stale candidate cannot publish after adoption. A ready candidate can be adopted without rebuilding deleted inputs. Published/retired output is never rewritten by resume. Final staging deletion and ready transition are idempotent. Cleanup removes the journal as well as all exact generation output and staging before freeing its slot.

## One cut ledger and truthful publication outcomes

`refresh({ cutAt, expectedActive, acquire, resumeRunId? }, budget, context)` retains the original cut/run ID, source evidence, budget and final deadline. Without `resumeRunId`, duplicate scheduled cuts still reject. Lost ledger insert/update replies are read back using the same logical identity and revision; no missing reply grants new work or time. Revision guards prevent a stale in-memory ledger from overwriting a newer attempt. Non-Error acquisition rejections are normalized without logging their raw value.

Resume checks the prior Builder slot and publication receipt before acquisition/build. A committed uncertain publication returns `published-reconciled` with its actual publication identity; it does not reacquire source, start another generation or increment publication again. The original commit time is not invented. A missing/unobservable receipt, unsafe predecessor or exhausted remaining reserve stays protected. A settled ready candidate finishes through the same generation.

The original 11:00/23:00 Bangkok, 12/2/6/4 allocation remains. Retry gaps, source revalidation, queue/cleanup/read waits and resumed work consume the same remaining reserve. Wall-clock gaps and persisted monotonic elapsed lower bounds survive process replacement; the new process measures only its new monotonic segment. Backward clocks fail. Database dispatch uses the stricter remaining positive bound. A retry never receives a fresh six-hour build allowance or another four-hour reserve; insufficient time fails freshness acceptance while previous full output/time stays truthful.

## Actual lifetime proof and narrow supervision

Write-concern, retryable, stepdown and driver errors are not automatic completion certificates. Rejected noncursor mutations require independent completion proof. A missing driver reply retains ownership even after an empty snapshot, because the command could still arrive later. A failed index operation retains ownership because background completion/tag association cannot be established by one empty tagged snapshot. Cursor close, kill acknowledgement, socket close, Promise completion, heartbeat/lease expiry and process disappearance do not authorize unsafe deletion. A failed drop with an actual terminal server response can finish verified D after independent observation; a lost transport reply stays protected. Exact durable control/ledger transition readback is a separate proof for those idempotent transitions.

The private supervisor creates the actual Worker itself with a fresh random incarnation and dedicated channel before model dispatch. It accepts only its own registration object, so an unrelated Worker cannot be paired with a persisted incarnation. A supported worker recovery pauses at a genuine settled checkpoint: stop new scope dispatch, await registered tasks/cursors and pending heartbeats, then acknowledge a private checkpoint epoch. Resume requires that current acknowledgement and revokes proof before allowing new dispatch. Stale/repeated epochs cannot restore it.

Only an actual exit of that registered Worker while the checkpoint gate remains closed, followed by independent database completion observation, can settle its owned slot/pins. The verified observer remains local no-auth standalone only. Replica-set, sharded/auth visibility, failed-index completion, lost supervisor state and unregistered workers remain unsupported/protected. Arbitrary mid-command crashes remain occupied even if a current-operation snapshot is empty: a real request delayed before the server could still arrive later. This ticket explicitly tests that late-arrival case and does not claim generic process/failover termination capability.

## Public-seam regressions and report

Twenty new integration cases use real isolated MongoDB, actual Workers, existing HTTP controllers and bounded wire faults. No repository function is mocked and no test-only HTTP API is added. They cover write-concern uncertainty, exact-source/clock/budget resume, zero-stage repaired transport, corrupt finalized summaries, dictionary/month/snapshot/comparison failures, terminal versus missing stage-drop replies, lost ready/ledger/publication replies, original reserve exhaustion, mismatched Worker association, checkpoint crash recovery and queued pre-server requests. Existing cancellation, shared demand, real reader loss, suspect leases, control limits, two-slot retention and publication/deletion race coverage remains applicable.

Observed red/green failures included unsafe cleanup after a real driver write-concern error; a new generation instead of same-cut resume; losing D after staging deletion; a null acquisition rejection erasing failure reporting; abandoned committed ledger insert; Builder busy state poisoned by a rejected budget change; ready adoption creating a second candidate; uncertain publication repeating build/publish; unrelated Worker association; late pre-server request incorrectly authorizing reclaim; early resume without checkpoint acknowledgement; a zero-stage failed slot blocking its repaired cut; overwritten original acquisition/build timestamps; and a missing transport reply incorrectly allowing D finishing. Each targeted change was exercised at the accepted public boundaries. The initial lost-drop success was narrowed after the queued-command regression showed why a generic empty snapshot cannot establish transport completion.

[The repeatable report](ticket-28-fixture.json) reuses ticket 27's complete finite raw source/correction cases and archived baseline revision. It independently runs baseline ETL/controllers again and compares 21 cases × six routes × two source revisions: 252 complete status/body comparisons. It records exact reference/actual body digests, full national bodies, all six parsed-body timers, source headers and state, actual stage inventories/times/resources, occupied/control identity, one-heavy-operation observation and idempotent cleanup. It preserves the real monthly validation failure and six unchanged old responses, corrupts the completed summary fixture, then demonstrates verified A reuse and full dependent rebuild. The old/new correction cases include history older than the migration/current graphs, deletion/replacement, eligibility/geography/category moves and surviving patient/hospital/scalar contributions.

Synthetic source/calculation times establish fixture behavior only. Execution duration/resource observations do not establish representative host headroom, aggregate serving/refresh memory, database memory, 20/100-load p95, actual source ingestion or visible 24-hour page acceptance. No patient identifiers, credentials or internal hosts are included.

The final report ran in 24.339 seconds. Observed peak additional Builder RSS was 48,513,024 and 38,223,872 bytes for the initial and recovered candidates; measured peak serialized buffers were 150,072 and 150,088 bytes; peak accounted storage was 778,427 and 1,806,247 bytes. Storage is checked after journal writes and before finishing recovery as well as at ordinary stage boundaries. Final control had revision 1469, fence 3, publication version 2, one occupied slot, zero pins and 3,118 BSON bytes. The failed month's actual terminal response plus application quiescence and verified standalone observation supplied its settlement proof. The report does not extrapolate these observations to target capacity or other topology.
